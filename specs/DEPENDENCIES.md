# Dependencies

> Last updated: 2026-08-22

Skriv has no package manager, build step, or runtime CDN dependency. Third-party browser distributions are pinned, checked into `public/`, and included in the service-worker inventory.

## Vendored third-party code

| Library | Version | Local files | Consumer | Purpose |
| --- | --- | --- | --- | --- |
| Tailwind CSS browser build | 3.4.17 | `public/vendor/tailwindcss-3.4.17.js` | `index.html`, `whitepaper.html` | Utility CSS generation in the browser |
| jsPDF UMD | 2.5.1 | `public/vendor/jspdf-2.5.1.umd.min.js` | `text-export.js` through `window.jspdf` | PDF generation |
| Floating UI DOM | 1.7.5 | four ES modules in `public/js/editor-core/vendor/` | `editor-toolbar.js` | Selection-toolbar positioning |
| Papertek Leksihjelp | 3.0.9, commit `62719ec1fe67ae60e3fe96293de2673acedf92eb` | `public/js/leksihjelp/` | classic scripts + app bridge | Local spelling, grammar, dictionary, and special-language support |

The pinned Tailwind and jsPDF files have repository tests for their exact expected SHA-256 hashes. The Leksihjelp snapshot is generated by `scripts/sync-leksihjelp.js`; its `.version` and file inventory are authoritative and its generated files must not be hand-edited.

Rules for a dependency change:

1. Pin an exact version and check the distribution into `public/vendor/` or `public/js/editor-core/vendor/`.
2. Record its version and purpose here and in `ARCHITECTURE.md`.
3. Add every runtime file to `sw.js` and bump the Skriv cache version.
4. Keep the critical install list atomic. Very large optional inventories may use the documented best-effort group.
5. Do not introduce a runtime CDN, tracking endpoint, or server request.

### Vendored classic-script graph

`index.html` loads `leksihjelp-loader.js` first, then the generated Leksihjelp classic scripts in their documented dependency order, then `app/main.js`. The loader supplies the narrow `chrome.runtime`/`chrome.storage` compatibility seam and binds it to `app/leksihjelp-bridge.js`. These files communicate through explicitly published `window.__lexi*` globals rather than ES-module imports.

## Invariants

- The complete internal import graph must remain acyclic.
- `shared/` never imports upward.
- `editor-core/` has no implicit dependency on `app/` state.
- Every new/renamed/removed module updates this graph, `MODULES.md`, and `sw.js` in the same change.
- Every dynamically imported module and leaf dependency is still part of the offline asset inventory.
