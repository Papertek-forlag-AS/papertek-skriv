# Dependencies

> Last updated: 2026-08-23

Skriv has no package manager, build step, or runtime CDN dependency. Third-party browser distributions are pinned, checked into `public/`, and covered by the service-worker policy: ordinary runtime files are inventoried for caching, while the MSAL response bridge is explicitly network-only. The optional Microsoft 365 connector makes direct browser requests to Microsoft identity and Microsoft Graph only after explicit configuration and user action; no Skriv application library is imported from either service.

The pinned Tailwind, jsPDF, and MSAL Browser distributions have repository tests for their exact expected SHA-256 hashes. The MSAL Browser 5.17.3 main distribution hash is `9b890db3ff7c399318b805665a13fb89006ced0baaac351ffd1c77bd39e5b652`; its redirect bridge hash is `3c26e0500ca46e53386c95c120b22a7fc9023ab55142206c4130c54379ecf5d1`. The Leksihjelp snapshot is generated by `scripts/sync-leksihjelp.js`; its `.version`, classic-script order, and file inventory are authoritative. The generated vendor files, the managed `index.html` script block, and the managed `sw.js` inventory must not be hand-edited.

Rules for a dependency change:

1. Pin an exact version and check the distribution into `public/vendor/` or `public/js/editor-core/vendor/`.
2. Record its version and purpose here and in `ARCHITECTURE.md`.
3. Add every cacheable runtime file to `sw.js` and bump the Skriv cache version. Authentication response resources that must remain network-only belong in the explicit service-worker bypass set instead of `ASSETS`.
4. Keep the critical install list atomic. Very large optional inventories may use the documented best-effort group.
5. Do not introduce a runtime CDN, tracking endpoint, or Papertek document/token server request. Any optional external service must be explicit, documented, least-privileged, and unable to block the local editor.

`document-store.js` and `folder-store.js` are intentionally one-way: the document module reads school-year state from the folder module, while the folder module mutates document records directly through the central database rather than importing the document module. This avoids a cycle.

### Vendored classic-script graph

`index.html` loads `leksihjelp-loader.js` first, then the generated Leksihjelp classic scripts in upstream manifest order, then `app/main.js`. Required global seams include rule-feature gating before the spell core and pedagogy/personalization helpers before the renderer. The loader supplies the narrow `chrome.runtime`/`chrome.storage` compatibility seam and binds it to `app/leksihjelp-bridge.js`. These files communicate through explicitly published `window.__lexi*` globals rather than ES-module imports.

MSAL Browser is not loaded from `index.html`. `microsoft-auth.js` injects `/vendor/msal-browser-5.17.3.min.js` on first connector use and then consumes its `window.msal.PublicClientApplication` global. Its cache location is `sessionStorage`. Popup flows use exactly `/microsoft-auth-redirect.html`; that page loads `/vendor/msal-redirect-bridge-5.17.3.min.js` and calls `msalRedirectBridge.broadcastResponseToMainFrame()`.

The redirect page and bridge are deliberately absent from the precache inventory and are explicitly bypassed by the same-origin fetch handler. The hosting layer must return `Cache-Control: no-store` and omit `Cross-Origin-Opener-Policy` for both URLs. A meta cache directive is defense-in-depth, not a substitute for the HTTP response headers.

### Optional external service boundary

The connector is disabled without valid client/tenant/bare-SharePoint-host configuration and explicit user action. When enabled, its only external runtime boundaries are:

- `https://login.microsoftonline.com/{tenantId}` for delegated Microsoft authentication;
- `https://graph.microsoft.com/v1.0` for folder/file metadata and upload-session creation; and
- exactly the configured `<tenant>.sharepoint.com` or matching `<tenant>-my.sharepoint.com` host for accepted sharing/canonical item URLs; and
- the short-lived HTTPS `@microsoft.graph.downloadUrl` or upload-session URL returned by Graph for file bytes.

Transfers are limited symmetrically to less than 60 MiB. Upload size is checked on exact UTF-8 bytes. Import checks Graph `driveItem.size`, `Content-Length`, and the accumulated response stream before fatal UTF-8 decoding; missing length metadata cannot turn the import into an unbounded `response.text()` read. Every authenticated Graph request and preauthenticated transfer uses `cache: no-store`, omits ambient credentials/referrers, and bypasses the service worker. Remote listing stops with a localized error beyond five Graph pages or 200 `.skriv` files.

The Graph scope is exactly delegated `Files.ReadWrite.All`, which is required for group-owned Teams/SharePoint files and remains bounded by the signed-in pupil's own access. Skriv additionally enforces its selected-folder boundary in code. There is no app-only credential, Papertek proxy/backend, analytics endpoint, Teams/channel enumeration, or application-library CDN download. Cross-origin responses and the two same-origin redirect resources are outside the Skriv service-worker cache.

## Invariants

- The complete internal import graph must remain acyclic.
- `shared/` never imports upward.
- `editor-core/` has no implicit dependency on `app/` state.
- Every new/renamed/removed module updates this graph, `MODULES.md`, and `sw.js` in the same change.
- Every dynamically imported module and leaf dependency is still part of the offline asset inventory.
